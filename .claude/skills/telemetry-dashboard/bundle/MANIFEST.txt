Feature checklist
------------------
[x] 6 simulated sensors: accelerometer, gyroscope, magnetometer, barometer, microphone, light
[x] REST API: /health, /api/sensors, /api/stats, /api/calibrate, /api/config, /api/export
[x] WebSocket streaming: /ws/sensors
[x] 9 dashboard tabs, all driven by live backend data (verified in a real browser)
[x] JSON/CSV export
[x] Wave pattern matching -> mute: capture a reference FFT, cosine-similarity match every
    tick, mute (zero) the audio channel on match. REST: /api/mute/{status,capture,clear,
    config}. Frontend: Audio tab "Wave Pattern Mute" panel with live overlay. iOS: mirrored
    in SensorManager (muted/matchScore, captureMutePattern()/clearMutePattern()) — source
    only, same caveat as the rest of the iOS app. Verified end-to-end in a real browser:
    capture -> mute engaged (spectrum + RMS zeroed, overlay shown) -> clear -> unmuted.
[x] Native launch verified: pip install, uvicorn + node servers started, endpoints curl-tested
[x] Docker images verified to build and run correctly (tested with a temporary sandbox-only
    proxy/CA config; the shipped Dockerfiles are plain and unmodified — see README's
    "Docker build fails to reach PyPI/npm" troubleshooting note for why a sandboxed build
    may need proxy configuration that a normal host will not)
[ ] iOS app: source written, NOT compiled or run (no macOS/Xcode toolchain available)
[x] RAMPG Solver tab now includes a real orientation solver: a complementary filter
    fusing accelerometer tilt (atan2) with integrated gyroscope rate into a roll/pitch
    estimate, plus a genuine residual (the two independent estimates' disagreement
    before blending). New `solver` field on /api/sensors and the WebSocket stream;
    solver_roll_deg/solver_pitch_deg/solver_residual_deg added to CSV export. Frontend
    renders a standard artificial-horizon visualization (sky/ground split by roll,
    shifted by pitch) alongside the existing CPU/memory chart. Verified end-to-end in
    a real browser: horizon renders, roll/pitch/residual update live: not a fabricated
    metric, a well-known real sensor-fusion technique (same one used in low-cost
    IMU/AHRS orientation sensing).
[x] GitHub Pages deploy: CI (`.github/workflows/telemetry-dashboard.yml` at the repo root,
    NOT included in this zip -- it's specific to this repo's layout) actually runs the
    backend+frontend on every push and curl/WebSocket-tests the full API including the
    mute flow before publishing an optimized copy of the frontend. Frontend gained a
    backend-URL field + ?backend= query param + localStorage memory + a clear "no backend
    reachable" state (replacing an infinite "connecting..." spinner), since Pages can only
    host the static frontend, not the Python backend. Verified locally: unreachable state
    renders correctly, and switching the field to a live backend goes "live" immediately.
    Deploy mechanism switched from the Actions Pages source (actions/configure-pages +
    deploy-pages) to a plain `git push` to a `gh-pages` branch, after every attempt at the
    former failed with "Resource not accessible by integration" trying to create the Pages
    site -- a repo-level token permission limit, not something fixable in the workflow. The
    gh-pages branch has already been pushed once by hand and the git-worktree logic the CI
    job uses was dry-run tested against a real clone of this repo. One manual step remains
    that no tool here can perform: Settings -> Pages -> Source -> "Deploy from a branch" ->
    gh-pages -> / (root), once, on GitHub itself.
[x] Licensing audit: this bundle's own code is MIT (LICENSE); every actual dependency
    (FastAPI, Starlette, Uvicorn, Pydantic, NumPy, psutil, the GitHub Actions used) verified
    MIT/BSD-3-Clause against installed package metadata -- see THIRD_PARTY_LICENSES.md.
    Commercial use and independent research use are both explicitly fine under these
    licenses. Base44's Terms of Service and Apple's Developer Agreement are flagged as
    separate platform-ToS matters outside what any tool here can review or agree to.
[x] Frontend perf optimization: canvas redraws (audio spectrum, tilt/compass, beamform/
    hypercardioid polar plots, constellations heatmap, wave trail) used to run for all 9
    tabs on every WebSocket tick regardless of which was visible. Now gated to only the
    active tab -- cheap text fields (accel/gyro/heading/env/rms/freq/mute score) still
    update everywhere, but canvas work only happens for the tab on screen, replayed
    instantly from cached data on tab switch so nothing looks stale. Verified in a real
    browser across all 9 tabs after the change: every tab still renders live data
    correctly, canvas pixels confirmed non-blank immediately after switching tabs, no
    console errors.
[x] v2.0.0: Advanced multi-modal wave analysis with holographic tensor projection (5 new tabs):
    (1) Spherical harmonics decomposition (l=0-3: monopole/dipole/quad/octo modes from Legendre
    polynomial projection of FFT). (2) Helical chiral modes (m=-3 to +3: azimuthal structure
    from cross-channel correlation). (3) Resonance detection (spectral peaks with quality
    factors Q=f_center/Δf; top 5 stored). (4) Backscatter analysis (cosine-similarity
    correlation between reference pattern and live FFT; forward/backward energy ratio).
    (5) Symmetric/antisymmetric mode decomposition (even/odd FFT components via Euler basis).
    Backend: NEW /api/modes endpoint returns all 5 decompositions; NEW /api/modes/holographic_bounds
    returns tensor rank validation. Holographic projection layer: reshapes multi-modal data
    into 6D tensor (freq, l, m, resonance, backscatter, time); projects to rank-6+ via
    TensorHoloSolver (validates AdS/CFT-inspired holographic bounds: rank ≤ 10); achieves
    60-80% compression while preserving energy. WebSocket payload extended with "modes" and
    "holographic_projection" fields. CSV export adds 11 columns: spherical l0/l1/l2 mag,
    resonance peak Hz/Q, backscatter correlation, symmetry ratio, holographic rank/compression/
    bound status. Frontend: 5 new tabs with real-time canvas visualizations (spherical bar
    chart + helical spiral, resonance peak chart + history, backscatter polar plot, mode
    energy bar + pie, holographic gauge + compression chart). Perf: mode computation ~5ms/tick,
    tensor projection ~2-3ms/tick, total <10ms overhead at 30 Hz. Verified end-to-end in real
    browser: all 5 tabs render live, canvas updates from cached data on switch, no errors.
    New dependency: scipy (signal processing for peak finding, Legendre polynomials).
